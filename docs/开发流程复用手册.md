# 数据可视化作品全流程复用手册

> 依据《非遗星图》项目完整实战整理，覆盖：立项调研 → 数据管道 → 前端开发 → 测试构建 → 部署上线 → 常见问题。做新项目时按本手册流程执行，可大幅减少踩坑。

## 一、整体流程（8 步）

```text
1 调研立项 → 2 初始化工程 → 3 数据采集 → 4 清洗验证 → 5 数据分析
→ 6 前端开发 → 7 测试构建 → 8 部署上线
```

## 二、分步操作

### 1. 调研立项

- 查清竞赛/发布渠道的往届规则：主办方、赛制、时间节点、作品要求（如“全国大学生数字媒体科技作品及创意竞赛”官网 cmit.cn）。
- 找 1-2 个参考作品，**只借鉴方法链**（真实数据→清洗→可视化→互动→结论→叙事），不复制布局/文案/图表/配色。
- 输出 `docs/项目背景.md`：竞赛信息、研究问题、口径定义、禁止表述。

### 2. 初始化工程

- 目录结构（保持原始/中间/清洗/网页数据、脚本、文档分离）：
  `data/raw|interim|processed|reports`、`scripts/{collect,parse,clean,validate,analyze,export}`、`web`、`docs`、`tests`。
- `git init`，`.gitignore` 提前写好（node_modules、dist、缓存、本地参考资料）。
- **提交前必查**：`git status`、`git ls-files` 里有没有大文件/敏感文件——`git add -A` 会把不该提交的东西（如本地参考 PPT、密钥）一起提交，之后清除要重写历史。
- 基础文档：README、数据字典（先定口径）、数据源登记表。

### 3. 数据采集

- **先探测接口**：用官方页面 JS 找真实接口参数（本项目教训：筛选用“数字 ID”而非中文名，否则返回错误数据集）。
- 通用采集器（`scripts/lib/collector_base.py`）必须支持：合理 UA、请求间隔、超时、指数退避重试、断点续传、本地缓存、请求日志、失败记录、按 id 去重、原始响应归档、dry-run。
- **先试点后全量**：试点取一个完整类别/批次（100-200 条）验证字段结构，再全量。
- 原始数据永久保留，清洗结果另存，不覆盖 raw。

### 4. 清洗与验证

- 标准化：编号（NFKC 全角转半角、罗马数字统一）、地区（行政区代码映射，保留原文）、批次、类型。
- 去重组合键**按真实数据调整**（本项目：同项目同地区不同子项要加入子项名称，否则误判重复）。
- 自动验证 + pytest：编号格式、必填、重复、批次、类别、地区映射、关联匹配率。
- 人工抽样清单（每批次/类别/地区抽几条）留待人工复核。
- 官方汇总总量只作校验，不一致时输出差异报告，不偷偷补数。

### 5. 数据分析

- 至少覆盖：地区分布、批次演化、类别结构、传承/资源配置（透明指标：覆盖率、每百子项传承人数）。
- 每条结论附带证据：结论文本/对应指标/使用字段/筛选条件/数据版本/生成日期。
- 免责声明固定句式：指标仅反映公开数据配置情况，不代表官方濒危等级或保护成效评价。

### 6. 前端开发

- 技术栈：Vue 3 + TypeScript + Vite + ECharts + Pinia；单页长滚动 + 锚点导航 + 滚动高亮。
- 数据全部本地 JSON + 相对路径 `base: './'`，断网可用、子目录部署兼容。
- 设计系统用 CSS 变量（背景/主色/类别色/字号/间距/圆角/阴影）。
- 动效：滚动入场（Reveal，支持方向+延迟）、数字滚动（AnimatedNumber）、鼠标微光、卡片悬停；保持克制。
- 图表懒加载 + 两阶段渲染（先 0 值后真实值）让柱状图“长出来”；**进入视口才初始化**。
- 依赖匹配：vitest 与 vite 大版本要兼容（vitest3 ↔ vite5）。

### 7. 测试与构建

```bash
python -m pytest tests -q          # 数据管道
cd web
npm ci --no-audit --no-fund
npm run type-check
npm test
npm run build
```

- 模拟 CI 环境：`npx -y npm@10 ci --no-audit`（npm 版本不同可能暴露锁文件问题）。
- 提交前跑完整套件，全绿再上线。

### 8. 部署上线（重要）

**已验证可靠的方案：gh-pages 分支 + “Deploy from a branch”**

```powershell
# 1) 构建
cd web && npm run build && cd ..
# 2) 把 dist 提交到独立 gh-pages 分支（含 .nojekyll）
git checkout gh-pages
Copy-Item -Recurse -Force web\dist\* .
git add -A
git commit -m "update site"
git push origin gh-pages
git checkout main
```

- 仓库 Settings → Pages → Source = **Deploy from a branch** → branch `gh-pages`、folder `/ (root)`。
- 站点地址：`https://用户名.github.io/仓库名/`。

**GitHub Actions 方案**（标准流程，但个别账号的 deploy-pages 管道会卡死，见下文问题表）：官方工作流 = checkout → configure-pages → setup-node → npm ci → type-check → test → build → upload-pages-artifact → deploy-pages。

**备用平台**：Cloudflare Pages / Vercel 直接拖拽 `web/dist` 上传，3 分钟上线，免费，支持私有仓库。

## 三、常见问题速查表

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `git push` 连不上 github.com:443 | 网络被墙/无代理 | `git config --global http.proxy http://127.0.0.1:7892`（换成你自己的代理端口） |
| push 被拒 `reference already exists` | 远程已有 main（建仓库时勾了 README） | 新仓库直接 `git push -f origin main` |
| 误提交大文件/参考文件 | `git add -A` 全量添加 | `pip install git-filter-repo` → `git filter-repo --path-glob '*.pptx' --invert-paths --force`，并加入 .gitignore |
| `npm ci` 报 EUSAGE / Missing esbuild | vitest 大版本与 vite 不兼容（vitest4 要 vite6-8） | 降级/对齐版本后 `npm install` 重建锁文件 |
| `npm ci` 报 audit 接口错误 | 部分镜像不支持 audit | `npm ci --no-audit --no-fund` |
| 图表空白只剩背景 | `structuredClone` 深拷贝配置遇到 tooltip formatter 函数抛错 | 用“保留函数的深拷贝”再归零数据 |
| 柱状图动画看不到/提前播完 | 图表提前初始化（视口外） | 进入视口才初始化 + 两阶段渲染（0 值→真实值） |
| GitHub Pages 一直 `deployment_queued`/`in_progress` 后失败 | 该账号 Actions 部署管道故障；或旧部署残留 | API 取消旧部署 → 删除重建 Pages → 最终改用 gh-pages 分支部署 |
| 令牌（PAT）粘贴到聊天 | 临时使用 | 用后立即到 github.com/settings/tokens 撤销 |

## 四、Git 规范

- 提交信息：`chore:`/`docs:`/`feat:`/`test:`/`fix:`/`ci:` 前缀，小步提交。
- 分支：`main` 开发、`gh-pages` 发布；推 main 触发的工作流若会失败，可在 Actions 设置里禁用，避免红叉噪音。
- 大文件策略：>50MB 用 Git LFS 或直接不入库（放本地/网盘），原始数据保留在仓库需评估体积。

## 五、上线验收清单

- [ ] 数据为真实公开数据且来源可追溯（原始归档+登记表）
- [ ] ≥100 条有效记录；清洗/验证脚本可复现
- [ ] pytest / vitest / type-check / build 全绿
- [ ] 页面地图、图表、搜索、筛选、动效正常，无控制台错误
- [ ] 移动端可用；断网可演示
- [ ] README 含完整运行步骤；数据质量报告说明已知问题
- [ ] 部署链接可公开访问
