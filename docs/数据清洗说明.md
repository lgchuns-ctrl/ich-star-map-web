# 数据清洗说明（试点）

## 一、清洗流程

`scripts/clean/clean_pilot.py` 读取 `data/raw/projects/projects_raw.jsonl`，逐条标准化后输出：

- `data/interim/pilot_projects.csv`：子项口径（官方行记录展开）
- `data/processed/subitems_pilot.csv`：完整字段
- `data/processed/projects_pilot.csv`：独立项目口径（按项目编号去重聚合）

## 二、标准化规则

### 1. 项目编号

保留 `project_code_raw`（原始文本）与 `project_code_normalized`（标准化文本）：

- 全角转半角（NFKC），如 `Ⅱ—28` → `II-28`、`Ⅹ-1` → `X-1`；
- 去除空格与全角空白；
- 破折号/连字符统一为 `-`；
- 罗马数字统一为大写。

### 2. 项目名称

- 去除前后空白与 HTML 标签；
- 全角括号经 NFKC 转为半角括号；
- 保留括号内地区/子项说明（如 `苗族古歌（簪汪传）`），不轻易删除；
- 同一项目在扩展批次可能带不同子项名，按子项保留，不强制合并。

### 3. 地区

同时保留 `region_raw`（原文）与 `province`（标准化）：

- 优先按官方 `address` 行政区划代码映射（34+ 个省级单位，含 中直单位 990121、新疆生产建设兵团 990122）；
- 映射失败时从 `region_raw` 匹配省份名称；
- `city_code` / `county_code` 保留官方代码供全量阶段解析市/县。

### 4. 批次

解析 `rx_time`（如 `2006</br>(第一批)`）为 `batch_no` 与 `publish_year`；五个批次映射为 1-5。

### 5. 新增/扩展

`cate` 字段映射为 `entry_type`：`new` / `extension` / `unknown`。

### 6. 保护单位

保留 `protection_unit_raw` 与 `protection_unit_normalized`（去除标签、压缩空白）。试点数据 251/251 均有保护单位，无缺失。

### 7. 去重

子项组合键：`project_code + batch_no + region_raw + protection_unit_raw + entry_type`。试点验证重复数为 0。

## 三、人工修正

试点阶段未发现需要人工修正的记录。全量阶段将把保护单位疑似合并、跨省单位归属等条目写入 `data/manual_corrections/` 并记录修正前/后值与原因。
