# 成功推送与上线完整流程（实测版）

> 基于《非遗星图》项目多次实测跑通的流程整理。注意：**你的 GitHub 账号的 Actions 部署管道不可用**，所以不要用 GitHub Actions 发布；可靠路径是 **gh-pages 分支 + “Deploy from a branch”**。

## 一、一次性准备（每台电脑做一次）

### 1. 让 git 能联网（国内网络）

```powershell
git config --global http.proxy http://127.0.0.1:7892
git config --global https.proxy http://127.0.0.1:7892
```

（换成你自己的代理端口；`curl https://github.com` 能通即可。）

### 2. 登录凭据（只需一次）

```powershell
git config --global credential.helper manager
```

然后在自己的终端里推一次，浏览器弹出 GitHub 授权，登录后凭据会保存到 Windows 凭据管理器，以后不再弹窗。

### 3. GitHub 仓库准备

- 仓库必须 **Public**（免费 Pages 只支持公开仓库）；
- 把代码推上去后，打开 `仓库地址/settings/pages`：
  - **Source（来源）** 选择 **Deploy from a branch**
  - **Branch** 选 `gh-pages`
  - **Folder** 选 `/(root)`
  - 保存，等待 1-2 分钟。

## 二、每次更新网站（完整命令）

### 第 1 步：开发分支保持最新

```powershell
cd F:\大创\非遗星图——国家级非遗项目传承观察
git add -A
git commit -m "你的改动说明"
git push origin main
```

### 第 2 步：构建

```powershell
cd web
npm run build
cd ..
```

产物在 `web/dist`。

### 第 3 步：更新 gh-pages 分支并推送（核心）

```powershell
$tmp = Join-Path $env:TEMP ("ghpages_" + [guid]::NewGuid().ToString("N"))
git worktree add $tmp gh-pages
Set-Location $tmp
Get-ChildItem -Force | Where-Object { $_.Name -ne ".git" } | Remove-Item -Recurse -Force
Copy-Item -Recurse -Force "F:\大创\非遗星图——国家级非遗项目传承观察\web\dist\*" $tmp
New-Item -ItemType File -Name ".nojekyll" -Force | Out-Null
git add -A
git -c user.name="lgchuns-ctrl" -c user.email="lgchuns-ctrl@users.noreply.github.com" commit -m "update site"
git push origin gh-pages
Set-Location "F:\大创\非遗星图——国家级非遗项目传承观察"
git worktree remove --force $tmp
```

### 第 4 步：验证

```powershell
curl.exe -s -o NUL -w "%{http_code}`n" https://lgchuns-ctrl.github.io/ich-star-map-web/
# 应返回 200；浏览器打开并 Ctrl+F5 强刷
```

## 三、一键脚本（推荐）

项目里提供了 `scripts/publish_to_ghpages.ps1`，以后更新直接：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\publish_to_ghpages.ps1
```

脚本自动完成：构建 → 更新 gh-pages 分支 → 提交 → 推送 → 提示网址。

## 四、常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `git push` 连不上 | 未走代理 | 配置 http/https proxy（见上） |
| 推 main 后 Actions 红叉 | 该账号 Actions 部署管道不可用 | 忽略；或在 Actions 页面禁用该工作流；不要用它发布 |
| Pages 一直 queued/in_progress | 使用了 GitHub Actions 发布源 | 改用 **Deploy from a branch → gh-pages / (root)** |
| push 提示登录 | 凭据未保存 | `git config --global credential.helper manager` 后重推一次 |
| 误把大文件/参考文件提交 | `git add -A` 全量添加 | 提交前检查 `git status`；用 filter-repo 清理 |
| 忘了更新 gh-pages | 只推了 main | 每次上线都要执行第 3 步（或用脚本） |

## 五、新项目怎么套用

1. 复制本项目 `web/`、`docs/`、`scripts/publish_to_ghpages.ps1`；
2. 换成新项目的数据与文案；
3. 建新公开仓库，推 main；
4. 执行一次“发布脚本”，Pages 设置同第一步第 3 点；
5. 以后每次：改代码 → 推 main → 跑发布脚本。
